1 · Routing: exchange → queues → consumers

A message is published with a routing key. The exchange reads the key and routes a copy to each queue whose binding matches. Consumers read from their queue and acknowledge. Try switching the exchange type.

2 · Competing consumers (work queue)

One shared queue, three consumers at different speeds. Each task goes to exactly one worker; faster workers handle more. The default (nameless) exchange routes by queue name. Use "burst of 5" to see the queue buffer a spike.

3 · RabbitMQ vs Kafka — what happens to a message after it's consumed

Both sides receive the exact same messages. In RabbitMQ a message is deleted from the queue once a consumer acknowledges it (ack). In Kafka the messages stay in the log, and each consumer reads independently using its own offset. Publish a few messages, let consumer 1 read — then try consumer 2.
